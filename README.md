# india-supplier-verify

Автоматическая проверка индийских компаний из очереди: юрлицо, товар/HS, фактические отгрузки, риски.

## Что внутри

- `queue.json` — очередь компаний (8 262 записи: name, legal, hs, industry, pan, state).
- `RULES.md` — правила проверки. Читается агентом при каждом запуске, менять только осознанно.
- `agents.py` — мини-агент на DeepSeek: цикл function-calling с инструментами `web_search`, `http_get`, `finish`.
- `run.py` — берёт очередную порцию компаний своего шарда и по каждой прогоняет 4 роли, результат пишет в `results/<роль>/<slug>.json` (построчно, повторный запуск пропускает готовое).
- `.github/workflows/verify.yml` — 20 параллельных задач по 8 компаний, каждые 6 часов; результаты коммитятся обратно в репозиторий.

## Роли

| Роль | Что собирает |
|---|---|
| legal | юрлицо, CIN/LLPIN, PAN, GSTIN, штат регистрации, MCA-статус, выручка FY25/FY26 |
| ship | фактические отгрузки: экспорт (дата, направление, HS, B/L) и внутренний рынок (GST-оборот, тендеры) |
| prod | реальный товар по сайту/каталогу и правильный HS-6 вместо заявленного |
| risk | санкционные списки, суды, регуляторы, рейтинги, поставки в РФ/СНГ |

## Запуск вручную

```bash
export DEEPSEEK_API_KEY=...
SHARD=0 SHARDS=1 BATCH=4 WORKERS=4 python run.py
```

Опции: `BATCH` — сколько компаний за прогон, `WORKERS` — сколько агентов параллельно, `MAX_SECONDS` — бюджет времени (по умолчанию 5,5 ч, чтобы уложиться в лимит задачи GitHub).

## Секреты

`DEEPSEEK_API_KEY` задаётся в Settings → Secrets and variables → Actions. В коде и в истории ключа нет.

## Статус

- `results/` — по одному JSON на компанию и роль; наличие всех четырёх означает, что компания закрыта.
- Сводку можно собрать любым скриптом, читающим `results/*/*.json`.
